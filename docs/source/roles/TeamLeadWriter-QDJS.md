## 1. 角色定位

文档团队负责人（TeamLeadWriter）是「技术写作组（Owner）」这一干系人的**带队与统筹视角**：既对文档内核与流水线的搭建负责，也对模板规范、发布门禁与回滚把关负责。前端工程师作为 **门户（后置）** 的实现方与本角色产生交集，交集集中在四件事——**门户最小入口、外观 / 主题边界、权限分级落地、中文检索分词**。

- 技术写作组（Owner）总体定位：搭内核与流水线、定模板与规范、编排内容、把关发布与回滚，交付构建链、模板库、规范、站点。[来源：company_doc_init.rst §2.2.1.2 角色表]
- 最终方案为「**内核 + 门户**」两层：Sphinx 为生成内核，自建最小门户为入口；起步阶段可先用 Sphinx 自带静态站，**门户后置**。[来源：company_doc_init.rst §2.1.1 最终方案、§2.2.1.1 门户（可后置）]
- 前端工程师在主文档中的唯一定义：角色「**前端工程师（门户，后置）**」，主要工具 Next.js / Ant Design，在链条里「实现最小门户：检索、筛选、下载入口」，交付物「门户站点」。[来源：company_doc_init.rst §2.2.1.2 角色表]

> 前端工程师**不在**第 1 章 9 类干系人之列，也不在 HL-01~HL-04 各角色节中承担即时职责；其定义仅在 [第 2 章 · 技术方案](ManagementWriter.md) 的资源表里出现，且明确「后置」。本页所有前端职责均落在「门户」这一后置范围内。
> [来源：company_doc_init.rst §2.2.1.2、§3.2.1~§3.2.4]

## 3. 与前端工程师的协作接口

文档团队负责人与前端工程师的协作集中在以下四个接口，均落在「门户（后置）」范围内：

| 协作接口 | 文档团队负责人提供什么 | 前端工程师在其中做什么 | 来源 |
| --- | --- | --- | --- |
| 门户范围定义 | 定义门户只做**最小入口**（检索 / 筛选 / 下载），不重复内容生产 | 用 Next.js + Ant Design 实现最小门户 | company_doc_init.rst §2.2.1.2 角色表 |
| 外观 / 主题边界 | 定主题策略（stock + custom.css，只改观感不改结构），保持观感一致 | 在门户侧保持与静态站协调的观感，不擅自改内核结构 | company_doc_init.rst §2.2.1.1 技术选型表（主题） |
| 权限集成 | 协同运维 SRE 定三级权限（公开 / 内部 / 机密），落托管层 | 门户接入 SSO / 分组，按权限展示入口 | company_doc_init.rst §2.1.1、§2.2.1.1 技术选型表（托管与权限） |
| 检索体验 | 用 Sphinx 内置检索（中文分词缺口待补） | 在门户层决定检索 UX，评估补齐中文分词或接搜索服务 | company_doc_init.rst §2.2.1.1 技术选型表（检索） |

> 前端工程师在本项目中「无职责 / 仅消费」的 LL 不列举；主文档未提供独立的前端工程师 HLD 角色页（`docs/feature/hld/` 下无 `actors_frontend.md`），其职责以 [第 2 章 · 技术方案](ManagementWriter.md) §2.2.1.2 角色表与 §2.2.1.1 技术选型表为准。
