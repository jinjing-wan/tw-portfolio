# 参与者 · 研发部

:::{note}
本页为「公司文档初始化项目」参与者页面之一：**研发部**。
按底层级需求（LL）逐条列出该角色有实际职责的部分与具体做什么；无职责 / 仅消费的 LL 不列。
「主」表示该 LL 的主责模块。条目为示例数据。
:::

## 1. 角色定位

技术内容主责：HLD/API/安装部署三类模板主导，代码相邻文档迁入，PR 提交与三方评审，存量技术文档配合迁移。

## 2. 在各底层级需求（LL）中的职责

| LL | 具体做什么 |
| --- | --- |
| LL-001 | 将代码相邻技术文档（HLD/API）源文件迁入统一库 |
| LL-002 | 按规范组织代码文档目录 |
| LL-004 | 评审需求模板可落地性 |
| LL-005（主） | 主导 HLD 模板（架构分层/接口契约/ADR/评审记录） |
| LL-006（主） | 定义 API 注释/契约格式与自动生成规则 |
| LL-007 | 提供功能说明输入 |
| LL-008（主） | 定义构建/依赖说明 |
| LL-009 | 提供变更点/已知问题 |
| LL-010 | 以 PR 提交文档变更并参与三方评审 |
| LL-011 | 提供本领域存量文档清单并配合迁移 |
| LL-012 | 提供技术上手指引 |

> LL-003（权限）研发部为「按角色使用」，无建设职责，故不列。

## 3. 具体操作与配置

```bash
# 迁入统一库
git add docs/design docs/api && git commit -m "docs: migrate HLD/API sources"

# 提交文档变更（走 PR，不直接推 main）
git checkout -b docs/update-hld && git push -u origin docs/update-hld
```

- 头文件注释须符合统一 Doxygen 注释规范（自动生成的前置），补注释覆盖率基线是「全项目最大变量」；
- 作为三方评审的领域技术主管，评审意见留在 PR 上。
